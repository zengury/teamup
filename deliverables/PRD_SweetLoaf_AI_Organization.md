## 1. 项目背景

### 1.1 面包店现状

SweetLoaf 是台南一家主打欧式手工面包的烘焙店，目前有：

- **1 家门店**（位于台南东区，靠近南纺购物中心）
- **员工约 12 人**：店长 1 人、烘焙师 4 人、门店销售 4 人、后勤（采购/仓管）2 人、学徒 1 人
- **日均客流量**约 150-200 人，节假日可达 300+
- **产品线**：欧式面包（酸种、可颂、佛卡夏）、台式软包、节日礼盒、饮品

### 1.2 当前痛点

陈先生在经营中遇到了几个典型的中小烘焙店问题：

| 痛点 | 具体表现 | 影响 |
|------|---------|------|
| **经验流失** | 资深烘焙师老王的"独家发酵手法"只有他自己会，他休假时出品不稳定 | 品质波动，客户投诉 |
| **培训成本高** | 新学徒到岗至少 3 个月才能独立上手，期间需要师傅全程带 | 人力成本高，扩店难 |
| **流程不统一** | 早班和晚班的打面手法不同，出炉时间经常偏差 20-30 分钟 | 影响销售高峰期的产品供应 |
| **隐性知识难复制** | "盐可颂要烤到表面微焦但底部不能焦"这种经验全靠口传 | 无法标准化扩张 |
| **沟通效率低** | 每天早会口头交接，重要信息容易遗漏或记错 | 出错率约 8% 的订单需要返工 |

### 1.3 为什么是 AI Agent，而不是传统软件

陈先生尝试过用 Excel、纸质 SOP、甚至买过一套小型 ERP，但都失败了。原因很简单：

- **传统软件太死板**：面包店的工艺是"手感经验"，不是流水线，没法用 checkbox 管理
- **SOP 没人看**：打印出来的操作手册放在架子上积灰，员工更相信"师傅说的"
- **记录太麻烦**：让忙碌的烘焙师去系统里填表，等于增加工作量

**AI Agent 的核心价值**：让员工用最自然的方式（说话、拍照、简单点选）把经验留下来，然后 AI 帮他们整理成可复用的"技能包"（Skill），再嵌入到日常工作中自动生效。

## 2. 核心目标

陈先生提出的三大战略目标，我们拆解如下：

### 目标一：让每个员工都开始生产自己的 Skill

> **"把脑袋里的经验，变成店里的资产"**

- 烘焙师可以录制"我今天调整面温的心得"，AI 自动整理成可复用的技能包
- 销售可以记录"这种客人推荐哪款面包成交率最高"，变成销售技能
- 店长可以把"节假日备货的判断逻辑"固化为管理技能

**关键指标**：上线 3 个月内，人均创建 Skill ≥ 3 个；6 个月内，Skill 覆盖核心岗位的关键工序 ≥ 80%

### 目标二：构建新的业务流程，用 Skill 加速效率迭代

> **"让 Skill 不是放在柜子里，而是跑在流程里"**

- 新学徒上岗时，系统自动推送相关岗位的 Skill 包，边做边学
- 每天开工前，AI Agent 根据当天的天气、订单量、库存情况，自动组合相关 Skill 生成当日操作建议
- 出现品质问题时，AI 自动比对标准 Skill 和实际操作的偏差，定位问题环节

**关键指标**：新员工独立上岗时间从 3 个月缩短到 1 个月；品质投诉率下降 50%

### 目标三：给员工提供非常方便的工具

> **"简单到阿嬷都会用"**

- 语音输入为主：烘焙师满手面粉时，用说的就能记录经验
- 拍照识别：拍一张面包照片，AI 就能判断火候是否到位，并关联到对应的技能包
- 一键调用：员工不需要学习"系统操作"，只需要像聊天一样和 AI Agent 对话

**关键指标**：员工每日使用工具的主动操作步骤 ≤ 3 步；员工满意度评分 ≥ 4.5/5

## 3. 用户角色

### 3.1 角色总览

| 角色 | 人数 | 核心需求 | 技术舒适度 |
|------|------|---------|-----------|
| 烘焙师（含学徒） | 5 人 | 记录/调用烘焙工艺经验 | 低（满手面粉，没空打字） |
| 门店销售 | 4 人 | 产品知识、客户应对技巧 | 中（会用手机） |
| 店长 | 1 人 | 管理决策支持、流程监控 | 中（会用基本 App） |
| 后勤（采购/仓管） | 2 人 | 库存管理、采购决策经验 | 低（年纪偏大） |
| 老板（陈先生） | 1 人 | 全局效率数据、组织能力沉淀 | 高（主动推动数字化） |

### 3.2 详细角色描述

#### 🧑‍🍳 烘焙师 — 阿明（化名）

**背景**：32 岁，入行 10 年，SweetLoaf 的首席烘焙师。他有一套"独门发酵法"——根据当天温度湿度调整发酵时间，做出来的酸种面包全台南有名。

**痛点**：
- 他的经验只有他自己知道，休假时徒弟做的酸种就是差一口气
- 每天要重复回答学徒同样的问题："面温到多少可以开始打？"
- 想教但没时间，一炉面包的时间窗口就 15 分钟

**对 AI 的期待**：
- "要是能把我说的录下来，自动变成教学材料就好了"
- "徒弟操作时能提醒他注意关键节点，我就不用一直盯着"

#### 🧑‍💼 门店销售 — 小玲（化名）

**背景**：25 岁，前台销售，性格开朗。她能记住常客的喜好，但新来的兼职记不住。

**痛点**：
- 每天要回答几十次"这个面包是什么口味"
- 客人问"有没有适合糖尿病人的面包"时，她需要跑去问烘焙师
- 换季时新品信息靠晨会口述，经常记混

**对 AI 的期待**：
- "客人一问，我能马上查到答案，不用跑后场"
- "最好能告诉我这个客人上次买了什么，我可以推荐新品"

#### 👨‍💼 店长 — 志伟（化名）

**背景**：38 岁，管理门店 5 年。每天要盯着出餐节奏、人员排班、库存、品质。

**痛点**：
- 每天花 1 小时做日报，数据散落在各个地方
- 判断今天该备多少料全靠经验，经常备多或备少
- 想复制 SweetLoaf 开第二家店，但发现"标准流程"都在人脑子里

**对 AI 的期待**：
- "每天打开手机就能看到今天的运营建议"
- "我想把节假日备货的逻辑做成系统，以后自动算"

#### 👨‍🍳 学徒 — 小豪（化名）

**背景**：19 岁，刚入行 2 个月。热情高但经验少，经常犯错。

**痛点**：
- 师傅讲的时候好像懂了，自己做就忘
- 犯错后不知道错在哪里，也没人及时纠正
- 不好意思一直问，怕被嫌烦

**对 AI 的期待**：
- "我操作的时候有人提醒我下一步该做什么"
- "做错了能告诉我哪里不对，怎么改"

#### 👨‍💼 老板 — 陈先生

**背景**：45 岁，创业者，想把 SweetLoaf 做成连锁品牌。

**痛点**：
- 核心能力都在几个老员工脑子里，想扩张但不敢
- 没有数据支撑管理决策，凭感觉经营
- 想推动数字化，但怕员工抵触

**对 AI 的期待**：
- "我想看到每个岗位的效率数据，谁做得好、哪里可以优化"
- "我想把 SweetLoaf 的经验打包，开新店时直接复制"

### 4.2 模块一：Skill 创建与管理（核心功能 · Must Have）

这是整个系统的根基——让员工**轻松地把经验变成可复用的技能包**。

#### F1.1 语音记录经验

**用户故事**：
> **作为** 烘焙师阿明  
> **我想要** 在操作过程中用语音记录我的经验和判断逻辑  
> **以便** 不用停下来洗手打字，就能把经验保存下来

**验收标准**：
- [ ] 支持闽南语和普通话混合语音识别（台南员工习惯讲闽南语）
- [ ] 烘焙师说"今天天气比较冷，面温要打到 26 度，比平时高 2 度"，AI 能自动提取关键参数：`条件：气温低 → 面温目标：26℃（+2℃）`
- [ ] 语音记录后自动生成结构化 Skill 草稿，员工可一键确认或补充
- [ ] 全程无需打字，3 步内完成：① 点"录音"→ ② 说话 → ③ 保存

**真实场景举例**：
```
阿明在打面时觉得今天面团状态特别好，拿出手机对着 AI Agent 说：
"今天台南降温，室温只有 18 度，我用了温水打面，
  水温调到 35 度，面温打到 26 度就停了，
  发酵时间比平时多了 40 分钟，出来的气孔特别漂亮。"

AI 自动整理为 Skill：
┌─────────────────────────────────────┐
│ 技能名称：低温天气打面调整法          │
│ 触发条件：室温 < 20℃                │
│ 操作步骤：                           │
│   1. 水温调至 35℃（常温 +8℃）       │
│   2. 面温目标 26℃（比常温 +2℃）     │
│   3. 发酵时间延长 40 分钟            │
│ 预期效果：气孔更漂亮，口感更蓬松      │
│ 创建者：阿明 | 状态：草稿待审核       │
└─────────────────────────────────────┘
```

#### F1.2 拍照记录成品标准

**用户故事**：
> **作为** 烘焙师  
> **我想要** 拍一张成品的照片，让 AI 帮我记录这个批次的状态  
> **以便** 以后可以比对"什么样子是烤得刚刚好"

**验收标准**：
- [ ] 拍照后 AI 能识别面包的颜色、形状、表面纹理
- [ ] 自动关联到对应的产品 Skill（如"法棍 Skill"）
- [ ] 支持标注"合格/偏浅/偏深"，作为品质标准参考
- [ ] 照片自动存入该 Skill 的"成品图库"，形成视觉标准

**真实场景举例**：
```
阿明烤了一盘可颂，拍了一张照片上传。
AI 识别："表面金黄油亮，层次分明，底部浅褐色 — 判定：A 级（完美）"
自动关联到"可颂烘焙 Skill"，作为标准参考图。
下次学徒烤出来的可颂拍照上传，AI 自动比对："底部偏深，建议降低底火 5℃"
```

#### F1.3 技能库管理

**用户故事**：
> **作为** 店长志伟  
> **我想要** 查看和管理团队积累的所有 Skill  
> **以便** 确保技能质量，并决定哪些可以正式发布给全员使用

**验收标准**：
- [ ] 技能列表：按岗位（烘焙/销售/管理）、按产品（酸种/可颂/吐司）、按类型（工艺/判断/沟通）分类
- [ ] 技能状态：草稿 → 审核中 → 已发布 → 已归档
- [ ] 支持版本管理（阿明更新了"低温打面法"v2，旧版本自动存档）
- [ ] 支持点赞、评论（员工可以反馈"这个方法好用"或"我这里试了不行"）
- [ ] 搜索：支持关键词搜索（如"发酵""台风天""糖尿病"）

#### F1.4 技能模板引导

**用户故事**：
> **作为** 后勤阿姨美珍（50 岁，不太会用手机）  
> **我想要** 按照模板一步步填写，而不是从空白开始  
> **以便** 我也能贡献我的采购经验

**验收标准**：
- [ ] 每个岗位有预设的 Skill 模板（烘焙模板、销售模板、管理模板）
- [ ] 模板包含引导问题（如"什么情况下用这个技巧？""具体怎么做？""效果是什么？"）
- [ ] 支持语音回答引导问题，AI 自动填入模板

**真实场景举例**：
```
采购模板引导问题：
1. "你这次采购的是什么原料？" → 美珍说："面粉"
2. "你是怎么判断这家供应商的货好不好的？" → "看面粉的颜色，太白的不行，要带一点米黄色"
3. "还有什么要注意的？" → "夏天面粉容易长虫，到货要放冷冻 48 小时"

AI 自动生成：
┌─────────────────────────────────────┐
│ 技能名称：面粉采购验收技巧           │
│ 适用岗位：后勤/采购                  │
│ 判断标准：面粉呈米黄色为佳           │
│ 特殊处理：夏季到货需冷冻 48 小时     │
│ 创建者：美珍                         │
└─────────────────────────────────────┘
```

### 4.3 模块二：Skill 应用与流程集成（核心功能 · Must Have）

Skill 建好了要能用起来，而且要嵌入到日常工作流中。

#### F2.1 岗位技能地图

**用户故事**：
> **作为** 学徒小豪  
> **我想要** 看到我这个岗位需要学哪些技能，以及我学会了多少  
> **以便** 我知道自己该学什么、进度到哪里了

**验收标准**：
- [ ] 每个岗位有"技能树"：烘焙师学徒需要掌握 15 个核心 Skill
- [ ] 每个 Skill 标注状态：未学习 / 学习中 / 已掌握 / 可教授
- [ ] 系统根据小豪的操作数据自动评估掌握程度
- [ ] 达到"已掌握"后自动解锁下一个推荐学习的 Skill

**真实场景举例**：
```
小豪的烘焙学徒技能树：
✅ 基础打面法（已掌握）
✅ 基础发酵判断（已掌握）
🔄 整形手法（学习中，进度 60%）
❌ 烤箱温度控制（未学习）
❌ 酸种喂养（未学习）
❌ 可颂折叠法（未学习）
...
推荐下一步：学习"烤箱温度控制"——因为小豪最近有 3 次烤焦的记录
```

#### F2.2 实时操作指引

**用户故事**：
> **作为** 烘焙师（任何水平）  
> **我想要** 在操作时，AI 根据当前情况主动推送相关的 Skill 提醒  
> **以便** 我不需要停下来翻手册，边做边被指导

**验收标准**：
- [ ] 系统根据时间、天气、订单量、当前操作阶段，自动推送相关 Skill
- [ ] 推送形式：语音播报（戴蓝牙耳机听）+ 手机屏幕简短提示
- [ ] 推送内容：关键参数 + 注意事项，不超过 3 句话
- [ ] 支持"已读"和"收藏"（"这个提醒有用，我收藏"）

**真实场景举例**：
```
早上 6:30，阿明开始打面。
AI Agent 检测到：今日台南气温 32℃（高温日），湿度 85%
自动推送语音提醒：
"阿明注意，今天高温高湿，建议：
  1. 用冰水打面，水温控制在 12℃
  2. 面温目标 22℃（比平时低 2℃）
  3. 发酵时间缩短 30 分钟
  以上参考阿明上周创建的'夏季高温打面法'Skill"

阿明听完点点头："对，差点忘了今天要调。" 点击"已读"。
```

#### F2.3 问题诊断与纠偏

**用户故事**：
> **作为** 学徒小豪  
> **我想要** 当我做出来的成品有问题时，AI 能告诉我错在哪里、怎么改  
> **以便** 我不需要等师傅有空才能得到反馈

**验收标准**：
- [ ] 拍照上传有问题的成品，AI 自动比对标准 Skill 中的成品图
- [ ] 输出诊断结果："问题：底部烤焦 / 可能原因：底火过高 / 建议：降低底火至 190℃"
- [ ] 关联到对应的 Skill，自动标注"小豪在'烤箱温度控制'技能上需要加强"
- [ ] 支持追问："那如果我想补救这批面包怎么办？"

**真实场景举例**：
```
小豪烤了一盘盐可颂，底部有点焦。
拍照上传，AI 诊断：
"比对阿明师傅的'盐可颂标准烘焙 Skill'——
  问题：底部颜色偏深（你的 vs 标准：深褐色 vs 浅褐色）
  可能原因：烤盘放置位置偏低，离底火太近
  建议：下次将烤盘放在中下层（倒数第二层），底火设为 195℃
  补救：这批面包可以切除底部焦面，作为'特价款'销售"

小豪："学到了！" → 系统记录：小豪在"烤箱温度控制"技能上进步了。
```

#### F2.4 流程引擎（店长配置）

**用户故事**：
> **作为** 店长志伟  
> **我想要** 把多个 Skill 串成一个完整的业务流程  
> **以便** 每天开工时，系统能自动按流程运行

**验收标准**：
- [ ] 可视化流程编排界面（拖拽式，不需要写代码）
- [ ] 支持条件分支（"如果今天是节假日，执行节假日备货流程"）
- [ ] 支持触发条件（时间触发 / 事件触发 / 人工触发）
- [ ] 流程运行时可看到每个环节的进度和负责人

**真实场景举例**：
```
志伟编排了一个"每日开工流程"：

⏰ 05:00 → 系统读取今日天气 + 订单量 → 生成"今日烘焙计划"
             ↙ 如果是高温天 → 推送"夏季打面 Skill"
             ↘ 如果是雨天 → 推送"雨天发酵调整 Skill"

⏰ 06:00 → 烘焙师到岗 → 系统自动推送今日计划 + 相关 Skill 提醒
⏰ 07:00 → 第一批面包出炉 → 拍照记录品质 → 系统记录数据
⏰ 08:00 → 门店开门 → 推送"今日推荐话术"给销售
⏰ 10:00 → 销售高峰 → 系统监控库存 → 库存不足自动提醒补货
```

### 4.4 模块三：员工体验与易用性设计（核心功能 · Must Have）

这是陈先生特别强调的——**一定要简单**。

#### F3.1 入口即用：微信小程序 / LINE Bot

**用户故事**：
> **作为** 所有员工  
> **我想要** 不用安装新 App，用我每天都在用的微信或 LINE 就能用  
> **以便** 零学习成本

**验收标准**：
- [ ] 微信小程序或 LINE 官方账号作为主要入口
- [ ] 员工扫码即用，无需注册账号（手机号自动识别）
- [ ] 界面以"对话"为主，所有功能通过自然语言交互
- [ ] 支持语音消息输入（比打字更方便）

#### F3.2 语音优先交互

**用户故事**：
> **作为** 烘焙师（满手面粉）  
> **我想要** 全程用语音操作，不用碰手机  
> **以便** 不影响我的工作节奏

**验收标准**：
- [ ] 核心操作（创建 Skill、查询 Skill、记录问题）全部支持语音
- [ ] 支持免唤醒词连续对话（"帮我查一下昨天酸种的发酵温度"→ AI 回答后直接说"再帮我记录一下今天调了水温"）
- [ ] 语音反馈（AI 用语音回答，员工可以边做边听）
- [ ] 蓝牙耳机友好（所有语音提示可通过耳机播放）

#### F3.3 极简交互：三步原则

**用户故事**：
> **作为** 所有员工  
> **我想要** 做任何操作都不超过 3 步  
> **以便** 我不觉得"用系统"是个负担

**验收标准**：
- [ ] 创建 Skill：① 点"记录"→ ② 说话/拍照 → ③ 确认保存（3 步）
- [ ] 查询 Skill：① 问问题 → ② 看结果 → ③ 收藏/分享（3 步）
- [ ] 反馈问题：① 拍照 → ② AI 诊断 → ③ 看建议（3 步）
- [ ] 任何超过 3 步的操作都需要产品经理特批

#### F3.4 离线可用

**用户故事**：
> **作为** 烘焙师  
> **我想要** 在后场（信号不好的地方）也能正常使用  
> **以便** 不会因为网络问题中断工作

**验收标准**：
- [ ] 语音记录支持离线缓存，有网时自动上传
- [ ] 已缓存的 Skill 内容可离线查看
- [ ] 拍照先存在本地，有网时同步
- [ ] 离线状态下核心功能不中断

- [ ] 异常预警：品质合格率低于 90% 时自动推送通知

#### F4.3 品质追踪

## 7. 技术约束（给猴哥的参考）

以下技术要点供猴哥（技术负责人）参考，具体实现方案由猴哥决定：

| 约束项 | 说明 |
|--------|------|
| **语音识别** | 需支持闽南语 + 普通话混合识别，推荐使用云端 ASR 服务 |
| **图像识别** | 面包成色判断需要训练专用的图像分类模型，MVP 阶段可用通用视觉 API + 规则引擎 |
| **知识图谱** | Skill 之间的关联关系（如"高温天气"→"调整打面温度"→"调整发酵时间"）建议用知识图谱存储 |
| **前端框架** | 微信小程序 / LINE Bot 为主，建议用跨平台框架减少重复开发 |
| **后端** | 轻量级架构，MVP 阶段可用 Serverless 降低运维成本 |
| **数据存储** | 结构化数据（员工、Skill 元数据）用关系型 DB；非结构化数据（语音、图片）用对象存储 |
| **部署** | 建议部署在台湾本地云服务（如中华电信 hicloud 或 AWS 台湾区域），降低延迟 |
